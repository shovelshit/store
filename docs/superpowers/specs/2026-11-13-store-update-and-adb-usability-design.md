# Store APK 更新与 ADB 操作界面改版

状态：用户于 2026-11-13 回复“继续”确认本方案，进入实施。随后提供私有附件 asset 690802170 作为实际下载样例。

## 已核实的问题

- 1.3.0 的 MainActivity 没有版本检查、更新索引读取或自更新逻辑。
- AdbActivity 使用一个 ScrollView 堆放连接、完整 shell id、安装、应用和权限。没有显式返回栏，选中应用后权限被追加到整个应用列表后面。
- 权限直接显示英文名称和状态；完整 uid/groups 占据大量首屏；原生默认按钮占用过大。
- GitHub 下载点击会直接显示“已开始下载”，不能据此判断浏览器下载或 Android DownloadManager 已收到任务。实际故障另行复现，按证据修复，不把单元测试里的调用记录当成下载成功。

## 1. ADB 页面

采用一个原生 Activity 内的三个页签，切换页签保留当前连接、搜索条件和已选文件。

```text
← 返回                ADB 设备管理
● 已连接  设备型号 · Android 9
127.0.0.1:5555 · shell · 用户 0    [详情]
────────────────────────────────────
      设备         应用         安装
────────────────────────────────────
          当前页签的内容区域
```

- 返回栏和紧凑的目标状态固定在顶部，不随内容滚走。顶部返回与系统返回行为一致。
- 根页面返回退出 ADB；权限详情返回应用列表并保留搜索与位置。正在执行操作时，退出先确认取消，说明设备端已开始的安装可能继续。
- 默认仅显示设备型号、Android 版本、地址和 shell/root 身份摘要。完整 id/groups、连接错误详情放在可展开的“详情”中。
- 设备页：主机和端口紧凑布局，一行主操作“连接/断开”，清楚显示连接中、等待授权和失败；地址记忆沿用现有行为。
- 应用页：搜索和系统应用筛选固定在列表上方，应用用可滚动紧凑列表显示，点击后进入单独权限详情，避免在大量应用后寻找权限。远程名称无法取得时明确使用包名，不冒用本机同名应用信息。
- 权限详情：以中文名称为主，如“相机”“存储”“修改安全设置”“悬浮窗”；状态显示“已授权/未授权/未知”。默认显示应用已声明的相关权限，不能操作的项目说明原因。授予、撤销保留确认与实际状态回读。
- 安装页：文件卡片、选择文件、安装到目标设备和进度/结果集中展示。当前目标始终可见；下载管理的“ADB 安装”直接打开此页签并预选对应文件。
- 没有版本名的 APK 不显示字面量 null；横屏和窄屏验证返回、页签、搜索、确认按钮都可达。

## 2. 自动检查和应用更新

推荐自有域名静态更新索引。客户端直查 GitHub Releases 容易受到网络、API 配额和预发行筛选影响；增加 Worker 动态代理与缓存能解决部分问题，但增加服务端逻辑。本次使用已存在的静态资源部署链路，无需 D1、新密钥或 GitHub Token。

- 冷启动后后台检查更新，自动检查一小时内不重复；另提供始终可用的“检查更新”入口和当前版本信息，不依赖网页登录。
- 索引地址为 `https://store.ltools.asia/android/update.json`，由 Store 静态资源部署提供；不扫描仓库，也不让每台设备调用 GitHub API。
- 索引提供 schema、versionCode、versionName、APK HTTPS 地址、大小、SHA-256、签名证书 SHA-256、minSdk、发布渠道和更新说明。
- 比较 versionCode，只提示比当前更新且系统兼容的同渠道版本。开发签名版本和未来其他签名版本不能混用。
- 发现更新后显示版本与说明；用户点击更新后下载，页面显示真实进度与失败原因，完成后校验大小、SHA-256、包名、versionCode 及签名连续性，再进入 Android 系统安装确认。
- 不自动卸载旧版、不清除数据。签名不一致、文件损坏、返回 HTML 登录页、下载失败或索引不可用时，明确显示失败；不能显示“已是最新版”掩盖检查失败。
- 本次“自动更新”指自动发现新版本并完成用户确认后的下载与校验；安装保留 Android 系统确认。无人值守静默安装不纳入本方案。
- 下载与校验在后台执行，不阻塞主界面。退出页面后任务仍可查看；重复点击不建立多个相同更新任务。

### 发布时同步更新索引

- 构建产生 APK、SHA-256 和待发布更新描述，沿用 1.3.0 已保留的同一开发签名私钥。
- 先上传 Release 安装包与校验文件，重新下载核对后，再生成/更新静态索引并提交 Store 与父仓库 gitlink，触发既有自动部署。
- 提供索引生成/校验脚本，固定从 Manifest 与实际 APK 读取版本、包信息和哈希，防止手填版本错位。
- 安装包不可下载或哈希不一致时禁止更新公开索引。未来每次发版遵循同一流程，使已安装新版能自动发现后续版本。
- 1.3.0 没有检查更新代码，无法仅靠网站部署获得此功能，因此需要手动安装一次带更新功能的新包。

## 3. GitHub 下载故障

- 先复现公开直链、加速线路、同源私有附件在实际 DOM 和 APK 中的差异，记录点击、网络请求、下载任务、失败状态。
- 修复已证实的链接触发/原生接管问题，避免重复任务。公开下载保持普通浏览器可用，私有下载只对 Store 同源携带会话，绝不向外站泄漏 Cookie 或 Token。
- 网页无法知道系统已建立任务时，只提示“已请求下载，请查看下载列表”，不能谎报下载成功。原生提示以实际任务状态为准，完成广播也核对成功状态。
- 验证必须包含实际下载字节和大小/哈希；模拟已完成记录不能作为本次下载故障修复的成功证据。

## 4. 版本、边界和验证

- 改版版本拟为 1.4.0 / versionCode 6；与本次发布的 1.3.0 开发版保持签名连续，可覆盖该开发版。更早未知签名版本的兼容性仍不能保证。
- ADB 命令、认证协议、用户 0 范围和原生高权限边界保持原有约束，不增加 WebView ADB 桥或任意 shell 入口。
- 自动更新策略与索引解析进行独立行为测试，覆盖无更新、升级、降级、签名不符、坏文件、网络错误和重复请求。
- Android 9 验证首屏返回、权限详情返回、连接后切换页签、搜索、下载入口直接安装页、横竖屏以及更新下载/校验/系统确认。
- 修复实现、独立测试、独立验收依次进行；发布后独立验证远端 APK、更新索引与自动部署结果。

## 自查

- 明确区分自动检测与系统安装确认，不承诺静默覆盖。
- 自动更新不再增加每台设备对 GitHub API 的请求。
- 既有 1.3.0 需手动更新一次；后续版本依靠同签名与索引发现更新。
- 下载回归修复可以先独立验证，不受新功能界面方案审阅影响。
