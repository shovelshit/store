# Store APK：Android 9 ADB 工具设计草案

状态：用户于本会话回复“继续”确认，进入实施。

## 已知条件与目标

- 用户要求 APK 增加 ADB 提权、授权、安装能力，主要用于 Android 9。
- 用户确认设备已经开放 ADB，不需要开发电脑端开启 ADB 的流程。
- 现有包名为 `io.github.shovelshit.apkstore`，版本为 1.2.0 / versionCode 4。
- 当前 APK 使用原生 Java WebView 加载线上 Store，下载由 DownloadManager 管理。
- 当前已有普通安装、存储权限申请和“安装未知应用”设置引导；新增 ADB 功能保留这些入口。

## 方案选择

推荐 APK 内直接实现最小 Java ADB 客户端：无需额外安装服务，沿用现有无 Gradle 构建方式，也不需要为不同 CPU 打包 adb 二进制。

备选方案是内置原生 adb 工具，需要管理多个 CPU 架构的二进制、执行兼容性和额外包体；或接入 Shizuku，需要用户额外安装和启动服务。本次不采用这两种方式。

## 用户界面与行为

### ADB 连接

- 主界面增加“ADB 工具”原生入口，与现有“下载”入口并列。
- 默认连接本机 `127.0.0.1:5555`，允许修改主机地址和端口并记住设置。
- 显示未连接、正在连接、等待设备授权、已连接和失败状态，提供连接、断开、重试。
- RSA 认证所需密钥只保存在应用私有目录，重启复用；若设备弹出调试授权，提示用户在设备上确认。
- 连接成功读取实际 shell 身份、Android 版本和设备信息，页面始终显示当前目标设备。
- “ADB 提权”指通过已获授权的 ADB shell 执行操作；不将普通应用进程变为 root，也不承诺设备固件允许所有命令。

### 应用与权限

- 从当前连接的设备加载应用包列表，默认展示第三方应用，支持搜索和切换显示系统应用。
- 选中应用后展示包名、请求的权限及支持的授权操作；目标信息以连接设备为准，避免混用手机本地应用与远端应用。
- 提供 Android 9 常用运行时权限的授予、撤销，例如存储、定位、相机、麦克风；以目标应用声明和系统支持情况为准。
- 提供受支持的 ADB 授权快捷项：修改安全设置（WRITE_SECURE_SETTINGS）、悬浮窗、修改系统设置、使用情况访问。
- 危险运行时权限使用 pm grant/revoke；特殊访问权限按相应 app-op 或系统机制处理，不将它们全部当作普通运行时权限。
- 每次变更显示目标应用、具体操作和执行结果；执行后重新读取状态，不仅凭按钮点击显示“已授权”。
- 包名、权限名和命令参数严格校验，执行固定的功能命令，不提供任意 shell 终端。

### APK 安装

- 下载管理中已完成的 APK 增加“ADB 安装”，现有“安装”仍使用系统安装器。
- ADB 工具页提供选择本地 APK 的入口，通过系统文件选择器读取授权的文件。
- 安装前显示 APK 文件、能识别的包信息和当前目标设备；用户点击后执行安装。
- 通过 ADB 分块传输到目标设备独立的临时路径，完成后执行覆盖安装；不默认卸载、不自动清除应用数据、不默认允许降级。
- 显示传输进度、安装结果及签名冲突、版本降级、空间不足、设备策略拒绝等实际错误。
- 成功或失败后尽力清理本次临时文件；设备断连导致无法清理时明确提示。
- 普通安装不依赖 ADB；ADB 失败时保留用户手动改用普通安装的路径。

## 实现边界

- ADB 协议、RSA 认证、数据传输、命令执行与 Android 页面分开，便于使用本地假设备测试。
- ADB 操作在后台执行，带超时、输出长度限制和取消；页面销毁时关闭连接，避免阻塞主线程。
- 同一连接串行执行变更操作；切换目标或断开后，旧请求不得更新新目标的状态。
- 高权限入口仅在原生页面，不向远程 WebView 暴露执行 ADB 的 JavaScript 接口。
- 本次不修改 Store 账号、GitHub Token、Worker、D1 或 Movie 功能。

## 构建与交付

- 修正现有构建脚本写死 `.exe` / `.bat` 的问题，支持 macOS 与原有 Windows 构建。
- 使用独立的临时构建目录，不删除用户指定的 SDK、工程目录或共享目录。
- 新版本拟为 1.3.0 / versionCode 5，Manifest、构建产物名称和 User-Agent 同步。
- 保留现有签名；若现有签名不可取得，明确报告不能保证覆盖安装，不静默换签名。
- 交付可安装 APK、SHA-256 和操作说明。Git 提交、构建产物发布沿用用户已授权的交付流程；不以网页部署代替 APK 产物。

## 验证要求

- 协议测试覆盖连接、RSA 认证、分包读写、断连、超时和错误响应。
- 权限测试覆盖授权成功、未声明权限、app-op 被拒绝、命令参数校验和状态回读。
- 安装测试覆盖 APK 传输、成功、失败、断连、临时文件清理和覆盖安装参数。
- 保留原有下载、Cookie、普通安装和 Store 网页测试。
- 完成真实 Android 工具链编译、签名校验、包名及版本检查。
- 优先使用可用的 Android 9 模拟器验证原生界面和设备端行为；若没有用户车机或相同固件，明确区分模拟器验证与实际设备待验证项。
- 实现完成后依次进行独立测试与验收，分别记录结论。

## 草案自查

- 未将 ADB shell 与 root 混淆。
- 未把特殊访问权限当作普通运行时权限。
- 不依赖远程网页获得高权限；普通安装保留。
- 默认本机连接，修改目标时可见且隔离请求。
- 不涉及数据库迁移；不修改签名身份或用户应用数据。
