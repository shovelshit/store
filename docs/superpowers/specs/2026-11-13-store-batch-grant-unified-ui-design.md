# Store APK：应用一键授权与统一界面

状态：用户于2026-11-13回复“继续”确认本方案，进入实施。

## 目标与现状

用户要求 ADB 增加应用一键授权，统一 APK 界面风格，并解决车机 Dock 可能遮挡右下角三个悬浮入口的问题。

当前已发布版本为 1.4.0 / code6。MainActivity 的下载、ADB、更新入口分别使用蓝色胶囊、绿色矩形和灰色矩形，均为 FrameLayout 的 BOTTOM|END 覆盖层，底部固定18dp；下载进度同样覆盖在页面底部。代码没有系统 WindowInsets 处理。此布局存在被车机 Dock 覆盖的风险；尚未在用户车机上实测。

原生 ADB、下载管理、更新页分别创建控件：返回栏、按钮尺寸、圆角、颜色、间距不一致，更新页还存在直接使用像素间距的情况。网页 Store 已有稳定的蓝白配色，可作为统一基准。

ADB 目前仅能逐项授予，已具备受限命令、user0、权限声明检查、后台串行操作和变更后回读。批量能力沿用这些边界。

## 方案选择

推荐顶部固定工具栏：下载、ADB、更新入口不依赖屏幕底部位置；工具栏占据自身布局空间，不覆盖网页，入口始终可见。下载摘要放在该工具栏下方，只有任务存在时出现，不覆盖网页。

备选是横屏使用侧栏，适合宽屏但会占用仓库列表宽度，并增加横竖屏两套导航适配。另一备选是保留底部悬浮并允许拖动或设置高度，但仍依赖用户避让 Dock，位置和入口更难稳定。本次采用顶部工具栏。

## 一键授权

- 入口位于 ADB → 应用 → 指定应用的权限详情页，名称“一键授权”。显示当前目标设备、user0、应用包名与待处理数量。
- 范围为当前功能支持、应用已声明且当前可授予的未授权权限。沿用既有运行时权限和特殊访问支持；不承诺授权系统不可授予的权限。已授权项跳过，未声明、不支持、无法确认可操作的项目说明原因，不发出授予命令。
- 一次确认展示完整待授权清单与中文名称，包括修改安全设置、悬浮窗等特殊项，允许用户取消勾选。确认后按串行队列执行，不逐项再次弹窗。
- 确认执行前重新读取目标权限；执行中的目标和应用锁定。操作进度显示当前项目及已处理/总数，避免重复点击创建任务。
- 每项成功均以设备状态回读确认，不凭命令返回码宣布成功。单项拒绝记录原因后继续其他项目；断连、取消或目标失效时停止后续命令，保留已完成结果。
- 完成展示成功、已授权跳过、失败与未执行项目，并刷新权限列表；失败项可重新发起授权。取消不会自动撤销已经生效的权限。
- 保留逐项授予与撤销；不新增任意 shell、WebView 高权限桥、root 获取或批量卸载功能。

## 统一界面与车机适配

- 覆盖 APK 主工具栏、ADB、下载管理、应用更新及新增批量授权确认/结果界面；沿用 Store 网页蓝白设计，不重构网页业务功能。
- 共享颜色、字号层级、dp间距、圆角卡片、输入框、主要/次要/危险按钮、返回栏和状态展示规则。主色#2563eb、背景#f4f6fb、白色面板、正文#0f172a、次要文字#64748b；操作颜色表达语义，主要操作不再按页面随意换色。
- 工具栏为正常布局，下载/ADB/更新三个入口放在顶部；窄屏允许压缩标题或切换紧凑布局，所有入口保留文字与足够触控面积，不依赖悬浮拖动。
- 使用系统 WindowInsets 为原生根布局避让可报告的顶部、底部和侧边系统区域，并在窗口尺寸变化时更新。底部不放必要导航或关键固定按钮。
- 厂商 Dock 若覆盖窗口且不报告 Insets，不能保证检测其高度。通过顶部入口、可滚动内容与必要的内容末尾留白降低影响；不把系统 Insets 当作所有车机 Dock 的完整检测能力。
- ADB 保留设备/应用/安装页签、搜索位置和文件选择；权限详情的返回仍回到应用列表。下载和更新保留现有真实任务状态、校验及安装流程。
- 不新增 UI 框架或替换现有构建工具，仅提取适合当前原生 Java 页面复用的小型样式/布局组件。

## 验证与交付

- 批量授权覆盖：混合权限成功、已授权跳过、未声明/不支持跳过、特殊权限、单项拒绝后继续、回读不符、断连、取消和失败重试。测试确认 user0、包名及目标不会串用。
- Android9 自有测试设备验证真实批量授权和权限回读，确认返回、列表状态及重复点击行为。
- 检查横屏/竖屏/窄屏、带系统 Insets 和模拟底部 Dock 遮挡场景：顶部三个入口、返回和主要操作可达，网页不被导航及进度摘要覆盖。不把模拟遮挡说成用户车机实测。
- 回归下载、普通安装、ADB安装及原生更新检查，不改变现有登录、GitHub Token、后端、D1、Movie或调度。
- 独立开发、独立测试与实际验收依次完成。新版拟为1.4.1/code7，沿用保留的同一开发签名，可覆盖1.4.0；构建、远端安装包验证、更新索引和自动部署沿用已授权流程。

## 自查

- “一键”指一次确认后批量授予受支持项目，不宣称获得所有系统权限，也不绕过设备拒绝。
- 取消和部分失败均如实保留已生效结果，不给出虚假的事务回滚承诺。
- 顶部正常布局解决入口对底部位置的依赖；系统 Insets 与未报告 Insets 的厂商 Dock 明确区分。
- 方案批准不构成实现完成或用户车机验证通过；实现、独立测试、验收及发布分别记录证据。
